# Codebase Structure

**Analysis Date:** 2026-10-03

## Directory Layout

```
coika/
├── Assets/
│   ├── AddressableAssetsData/  # Addressables settings, groups (Core-Data, Theme-Cosmic, UI, FX, Audio-*, Scenes)
│   ├── Art/                    # Sprites (Background, Jar, Tiers), Atlases, Fonts, VFX
│   ├── Audio/                  # Music, Sfx, Mixer (placeholders)
│   ├── Data/                   # ScriptableObject assets: GameConfig, Themes, Tiers
│   ├── Input/                  # Coika.inputactions
│   ├── Prefabs/                # Jar, Piece, Particles, UI
│   ├── Scenes/                 # Boot.unity, GameScene.unity
│   ├── Scripts/                # All code, one asmdef per folder
│   ├── Settings/               # URP 2D renderer, volume profiles, build profiles
│   └── Tests/                  # EditMode and PlayMode
├── Packages/                   # manifest
├── ProjectSettings/
├── *.csproj, coika.slnx        # Generated by Unity
├── README.md
└── .planning/                  # GSD planning docs
```

## Directory Purposes

**`Assets/Scripts/Core/`:** `Assets/` (AssetService, SceneLoaderService, interfaces), `Boot/` (GameInstaller), `Pooling/` (PrefabPool). Namespace `Coika.Core`.
**`Assets/Scripts/Data/`:** `GameConfig.cs`, `SpawnSettings.cs`, `ThemeDefinition.cs`, `TierDefinition.cs`. Namespace `Coika.Data`.
**`Assets/Scripts/Gameplay/`:** all gameplay MonoBehaviours and logic; `Input/` subfolder for input abstraction. Namespace `Coika.Gameplay`.
**`Assets/Scripts/Tools/Editor/`:** editor menus (`TierDataSetup`, `ThemeValidator`, `JarPrefabTool`, `PiecePrefabTool`, `PlaceholderTierSpriteGenerator`, `AddressablesBuildMenu`).
**`Assets/Scripts/UI`, `Audio`, `Fx`, `Input`:** empty (`.gitkeep`); only UI has an asmdef.
**`Assets/Tests/EditMode/`:** pure-logic and prefab tests, `Fakes/` (e.g. `AllocationMeter.cs`).
**`Assets/Tests/PlayMode/`:** physics and scene tests, `Fakes/`.

## Key File Locations

**Entry Points:** `Assets/Scenes/Boot.unity`, `Assets/Scripts/Core/Boot/GameInstaller.cs`, `Assets/Scripts/Gameplay/DropControllerBootstrap.cs`
**Configuration:** `Assets/Data/GameConfig/GameConfig.asset`, `Assets/Data/Themes/Theme_Cosmic.asset`, `Assets/Data/Tiers/Tier_NN_Name.asset`, `Assets/Input/Coika.inputactions`
**Core Logic:** `Assets/Scripts/Gameplay/MergeSystem.cs`, `DropController.cs`, `SpawnQueue.cs`, `PieceFactory.cs`
**Testing:** `Assets/Tests/EditMode/`, `Assets/Tests/PlayMode/`

## Naming Conventions

**Files:** PascalCase matching the type, one type per file: `MergePairQueue.cs`; tests `<Type>Tests.cs`, PlayMode `<Type>PlayModeTests.cs`.
**Assets:** `Tier_NN_Name` (sprites and data), `Theme_Name`, `Jar_Part`.
**Directories:** PascalCase.
**Assemblies:** `Coika.<Layer>`; tests `Coika.Tests.EditMode|PlayMode`.
**Code:** UPPER_CASE constants (`CONTACT_TOLERANCE`), `_camelCase` private fields, XML doc on members, `[AddComponentMenu("Coika/...")]`.

## Where to Add New Code

**New gameplay feature:** `Assets/Scripts/Gameplay/<Feature>.cs`; tests in `Assets/Tests/EditMode/<Feature>Tests.cs` (logic) and `Assets/Tests/PlayMode/` (physics). Wire in `DropControllerBootstrap.cs` via `Initialize(...)`.
**New data definition:** `Assets/Scripts/Data/`, asset in `Assets/Data/`, mark Addressable in the proper group.
**New core service:** `Assets/Scripts/Core/<Area>/` with an `I<Name>` interface and a fake in tests.
**UI:** `Assets/Scripts/UI/` (asmdef exists; add references as needed).
**Editor tooling:** `Assets/Scripts/Tools/Editor/`.
**Utilities:** put pure helpers beside their users; no shared utils folder exists.

## Special Directories

**`Library/`, `Temp/`, `Logs/`, `UserSettings/`:** Unity generated; not committed.
**`Assets/AddressableAssetsData/`:** generated by Addressables, committed.
**`*.csproj`, `coika.slnx`:** generated.
