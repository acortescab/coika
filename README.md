# Coika

Drop cosmic bodies into a jar, merge identical pairs into bigger ones, and reach the Black Hole before the jar overflows.

Coika is a mobile (Android + iOS, portrait) pixel-art merge-physics game built with Unity. It is a premium game: no ads and no in-app purchases.

> **Status:** early development. Milestone M1 (playable core) is in progress.

## Requirements

- **Unity 6000.6.3f1** (see `ProjectSettings/ProjectVersion.txt`) with the Android and iOS build support modules
- Universal Render Pipeline (2D)
- Git

## Getting started

1. Clone the repository.
2. Open the project folder with Unity Hub using the editor version above.
3. Wait for the first import to finish.
4. Open `Assets/Scenes/Boot.unity` and press Play. `Boot` is the only scene in the build; it initializes Addressables and loads the game scene.

### First-time data setup

The tier data (sprites, theme and Addressable groups) is generated by Editor tools. Run them from the **Coika** menu if the assets are missing:

| Menu | What it does |
|---|---|
| `Coika/Setup Tier Data` | Generates the placeholder sprites, creates `Theme_Cosmic` and wires it into `GameConfig` |
| `Coika/Generate Placeholder Tier Sprites` | Regenerates only the 11 tier sprites |
| `Coika/Validate Theme` | Checks the theme: tier count and order, sprite sizes and Addressable groups |
| `Tools/Addressables/Build Content` | Builds the Addressables content |

## Project structure

```
Assets/
  AddressableAssetsData/   Addressables settings and groups
  Art/                     Sprites, atlases, fonts, VFX
  Audio/                   Music, SFX, mixer
  Data/                    ScriptableObject assets (GameConfig, tiers, themes)
  Prefabs/
  Scenes/                  Boot (initial build) and GameScene (Addressable)
  Scripts/
    Core/                  Services and composition root (Coika.Core)
    Data/                  ScriptableObject definitions (Coika.Data)
    Gameplay/              Game rules (Coika.Gameplay)
    UI/                    Views (Coika.UI)
    Tools/Editor/          Editor-only tools (Coika.Tools.Editor)
  Tests/
    EditMode/              Coika.Tests.EditMode
    PlayMode/              Coika.Tests.PlayMode
.planning/                 Design and engineering documents
```

Dependencies flow one way: `UI → Gameplay → Core`. `Data` depends on `Core`.

## Architecture in short

- **Everything except the boot scene is Addressable.** All scenes and assets are loaded through `IAssetService` and `ISceneLoader`; no other code calls `Addressables.*` or `SceneManager.LoadScene*` (constraint C-01).
- **No singletons.** `GameInstaller` in the `Boot` scene is the composition root: it creates the services and passes them to the rest of the code.
- **Data lives in ScriptableObjects** (`GameConfig`, `TierDefinition`, `ThemeDefinition`), so the theme can change without touching code.
- Every load has a matching release, and every load has error handling with retries.

## Tests

Open **Window > General > Test Runner**.

- **EditMode:** project rules (Build Settings, no `Resources/`, no direct Addressables calls, required groups) and the tier data.
- **PlayMode:** loads the game scene through Addressables. Set the Addressables **Play Mode Script** to *Use Asset Database*.
